# 测试与实测记录

运行方式（本目录为工作目录）：

```bash
python -m pytest tests/ -q
```

本地无 Docker/MySQL 时，按 `backend/tests/conftest.py` 的做法用 SQLite 与 fakeredis 即可跑全部测试；依赖为 `backend/requirements.txt` 外加 `pytest`、`httpx`、`fakeredis`。

## 覆盖与实测结果（2026-11-19，Python 3.11，320 项全部通过）

### 配对算法 `src/services/matching.py`（`tests/test_matching.py`）
- 最近项抢配：两条试封登记争同一漏封读数，时差 100 毫秒者配走，先登记者未配对。
- 目标优先级：两件配法（总时差 4800）胜过一件配法（总时差 100），先配最多件再让总时差最小。
- 同分配法改变计数：两条同时刻登记（一合格一失败）距同一读数都是 1000 毫秒，两种同样最优配法使合格数在 0/1 间变动，两侧分别验证拒绝出数且说明变动区间；候选记录结果相同（计数不变）时同样最优也正常出数。
- 三秒窗口边界：恰好 3000 毫秒可配，3001 毫秒不可配。
- 未配对计数、空流水、超一万条拒绝、超时拒绝（时限取负模拟）。
- 独立 oracle：300 个随机种子（0–4 条/侧、时刻取密集集合制造并列）对暴力枚举全部配法，逐一核对件数、总时差、两侧合格数与未配对数，歧义例（实测 28 例）必须拒绝、其余（272 例）必须出数且数值一致。
- 上限规模冒烟：10000+10000 条密集候选实测约 1.8 秒出数（5 轮字典序 DP），低于 5 秒时限。

### 冻结与补录 `src/services/streams.py`（`tests/test_streams.py`）
- 补录撞冻结：建分析后补录的记录 id 超过截点，已冻结分析重读结果不变、快照可复算同一结果；迟到记录只进新分析。
- 同一截点：两份流水共用全表同一 id 序列，新分析截点同时覆盖两侧迟到记录。
- 并发补录撞冻结：1 个线程持续补录、2 个线程同时建分析（SQLite，35 批记录），每份分析的快照与“该产线 id≤截点”的记录集完全一致，两份流水在截点处齐平。
- 重名源记录编号 409、空产线 422。

### API 冒烟（`tests/test_api.py`）
- 登录 → 批量录入 → 建分析 → 读取结果与计数；重名拒绝；非法枚举值 422；观察员只读（写操作 403）。限流中间件使用 fakeredis。

### 端到端演示（HTTP 全链路，TestClient）
- 场景1 最近项抢配：配对 1 件、总时差 100 毫秒，试封侧失败 1、未配对 1。
- 场景2 同分配法改变计数：refused，原因为“试封登记合格数可在0到1之间变动”。
- 场景3 补录撞冻结：分析截点 8，迟到记录 id=9 被排除且重读结果不变；新分析截点 9 含该记录。
